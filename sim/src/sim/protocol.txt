state:
per node:
	name: name of the node
	r: rolling run-time window (seeded, updated every run); r.p20 / r.p50 / r.p80
	pace: r at percentile PACE_PCT; used for best / worst              [changed, see 5]
	parents: list of parent edges
	children: list of child edges
	start: start timestamp of the current/last run
	end: finish timestamp of the last run
	last_idle_demand: time the last idle demand was sent
	seq[p]: per parent edge p, newest sample timestamp received on p
	        (0 until first data)                                       [changed, see 8]
	i: this node's own interval (from its last computed demand)
	w: idle heartbeat period (default 50ms; must exceed worst
	   expected latency spikes on network edges, since lease ≥ C × w)
	g: grace period for a join; UNSET = wait for all parents
	dc: per child edge, keyed by edge.end:
		exp: lease expiry time (absolute)
		i: send interval
		next: next send time (Source) / earliest next send (interior)
		last_seq: last accepted demand seq
		best, worst, phase: from the last accepted demand
		received: time that demand was received
		last_sent: producer id of the last output sent on this edge
		           (run id at engines, sample id at the Source)        [changed, see 4]
		last_send_t: time of the last send on this edge                [added, see 1, 3]
		pending: interior only: output waiting for this edge's next send slot
		waiting: Source only: a send slot found no new frame           [added, see 7]
per edge:
	begin: begin node
	end: end node
per demand:
	best: best-case arrival interval
	worst: path capacity
	phase: time until the next send (duration, measured at send time)
	seq: newest sample timestamp the sender has received on this edge; 0 = (re)starting
	lease: time the demand is active, anchored at receive time
per message (data):
	source: name of the source for the message
	seq: sample timestamp(s) of the data (lineage)
	producer: (node, run id) of the run that made it                   [added, see 4]
	data: message data (plus additional metadata to read it)
per message (control):
	demand | termination
per network edge:
	rtt: median of recent pings
	t = frame size × p<TRANSMIT_PCT>(recent arrival time per byte),
	    measured at RECEIVE side                                       [changed, see 5]
	Apply each exactly once: the RECEIVING side (child) folds in T before
	sending its demand (worst = max(worst, t); phase −= t); the side that
	measures RTT subtracts it (phase −= rtt).

constants: C ≈ 3 (≥ 2), ε ≈ jitter (≈ 1 ms locally),
	PACE_PCT = 50 (was 80), TRANSMIT_PCT = 50 (was 90)                 [changed, see 5]

NOTE: run each node as ONE event loop (events: data arrival, demand arrival,
termination, timers) instead of separate while-true loops. Separate loops
busy-spin and race on shared state (dc).

calc_lease(r, w) = C × max(r, w)

next_on_grid(t, i, now):
	# A schedule is a grid of send times t, t + i, t + 2i, ...
	# Return the first point on that grid that is not in the past.
	# Used when a send time has already slipped behind `now` (the demand
	# arrived late, or the timer fired late): skip the missed points
	# instead of sending a burst to catch up, and keep the original phase.
	if t >= now: return t
	k = ceil((now - t) / i)               # how many intervals we fell behind
	return t + k × i

calc_next_source(d, de, i, now):                                       [changed, see 2, 3]
	if d is unset or d.exp <= now:        # edge was not active
		return now                        # send immediately
	if de.seq == d.last_seq:              # renewal with no new data: keep the schedule
		return next_on_grid(d.next, i, now)
	# new data below: re-anchor on the demand's phase, but never send
	# sooner than I − ε after the previous send on this edge
	return max(next_on_grid(now + de.phase, i, now), d.last_send_t + i − ε)

calc_next_interior(d, de, i, now):                                     [changed, see 1]
	if d is unset or d.exp <= now:        # edge was not active
		return now                        # send immediately
	return d.last_send_t + i              # earliest next send; phase is not used

forward propagation:
source s:
	on timer (earliest d.next over live edges):
		for each edge e in s.children:
			d = s.dc.get(e.end)
			if d unset or d.exp <= now: continue
			if d.next <= now:
				f = s.newest_frame()
				if f.id > d.last_sent:
					e.send(f); d.last_sent = f.id; d.last_send_t = now
					d.waiting = false
				else:
					d.waiting = true                          # send the next frame on arrival
				d.next = next_on_grid(d.next + d.i, d.i, now)
	on new frame f:                                                    [added, see 7]
		for each live edge e with d.waiting and f.id > d.last_sent:
			e.send(f); d.last_sent = f.id; d.last_send_t = now
			d.waiting = false

interior node n (including joins; single-parent nodes are joins with one parent):
	on data arrival on parent edge p:
		fill p's slot (newer replaces older)              # late inputs are kept (may be stale)
		n.seq[p] = max(n.seq[p], newest timestamp in the input)
		if first unset: first = now
	run when:
		all slots full, or
		(n.g set and first + n.g <= now)                  # g unset → wait for all
	on run:
		x = n.collect(full slots)                         # empties the slots it takes
		n.start = now
		y = n.run(x)
		n.end = now; n.r.update(n.end - n.start)
		first = unset
		if y is None: return
		for each edge e in n.children:
			d = n.dc.get(e.end)
			if d unset or d.exp <= now: continue          # no demand: don't send
			d.pending = y                                 # newer replaces older
			try_send(e, d)
	on timer for edge e (d.next − ε):
		try_send(e, d)

	try_send(e, d):
		# Per-edge interval: the Source's interval follows the fastest child,
		# so at a fan-out this is what keeps slower children from receiving
		# every output.
		if d.pending set and d.pending.producer_id <= d.last_sent:   [changed, see 4]
			d.pending = unset                             # never send an output twice
		else if d.pending set and d.next − ε <= now:
			e.send(d.pending); d.last_sent = d.pending.producer_id
			d.last_send_t = now
			d.pending = unset
			d.next = now + d.i
		else if d.pending set:
			schedule timer at d.next − ε

leaf node l:
	same data handling as interior (slots, g)
	on run:
		x = l.collect(full slots)
		send_demand(l.parents, {                          # per parent p:
			best:  l.pace,                                             [changed, see 5]
			worst: l.pace,
			phase: l.r.p20,
			seq:   l.seq[p],
			lease: calc_lease(l.r.p80, l.w),              # leases stay on p80
		})
		l.start = now
		y = l.run(x)
		l.end = now; l.r.update(l.end - l.start)
		return y to the consumer of results

backward propagation:
leaf node l:
	at startup: send idle demand immediately
	on timer: if l is idle (no run in progress) and
	          now >= max(l.end, l.last_idle_demand) + l.w:
		send_demand(l.parents, {                          # per parent p:
			best:  l.pace,
			worst: l.pace,
			phase: 0,
			seq:   l.seq[p],
			lease: calc_lease(l.r.p80, l.w),
		})
		l.last_idle_demand = now

interior node n:
	on demand de from child edge e:
		d = n.dc.get(e.end)
		if d set and de.seq != 0 and de.seq < d.last_seq:
			return
		i = max(de.best, de.worst)
		n.dc[e.end] = {
			exp:         now + de.lease,
			i:           i,
			next:        calc_next_interior(d, de, i, now),
			last_seq:    de.seq,
			best: de.best, worst: de.worst, phase: de.phase, received: now,
			last_sent:   d.last_sent if d set else −1,
			last_send_t: d.last_send_t if d set else −∞,
			pending:     d.pending if d set else unset,
		}
		if n.dc[e.end].pending set: try_send(e, n.dc[e.end])
		maybe_send_up(n, trigger = e)

	maybe_send_up(n, trigger):
		live = [c for c in n.dc if n.dc[c].exp > now]
		c* = argmin over live of max(best, worst)          # fastest consumer
		send only if trigger == c*, or c* changed, or live set changed
		# age the stored phase: it was a duration from its receive time
		ph = next_on_grid(dc[c*].received + dc[c*].phase, dc[c*].i, now) − now
		g = { best: dc[c*].best,
		      worst: max(dc[c*].worst, n.pace),                        [changed, see 5]
		      phase: ph − n.r.p50,
		      lease: calc_lease(n.r.p80, n.w) }
		n.i = max(g.best, g.worst)
		send_demand(n.parents, g with seq = n.seq[p] per parent p)    # joins: same demand to every parent

	on lease expiry of child edge e (timer at dc[e.end].exp):
	on termination from child edge e:
		delete n.dc[e.end]
		if no live children: send termination to all parents
		else: maybe_send_up(n, trigger = e)               # c* or live set may have changed

source node s:
	on demand de from child edge e:
		(network edge: the side that measures RTT applies phase −= rtt
		 before the demand reaches s)
		same seq check and dc update as interior, with
		i    = max(de.best, de.worst, s.frame_period)
		next = calc_next_source(d, de, i, now)
		(the Source also keeps last_sent, last_send_t and waiting across demands)
		then re-arm the send timer
	on lease expiry / termination of child edge e:
		delete s.dc[e.end]                                # stop sending on e


changes from the original spec (each found in testing; see README.md):

1. Interior nodes pace each child edge by its interval only; phase does not
   set their send times. The original set an interior edge's `next` from
   the demand's phase (calc_next). That contradicts "the Source is the only
   place Phase sets a send time" (CLAUDE.md). Holding outputs until a phase
   point made them stale, and newer outputs then replaced them (wasted
   runs). An interior edge's `next` is now just the earliest next send,
   last_send_t + I, and an output is held in the edge's slot until
   I − ε has passed.
   The per-edge interval is still needed. The Source's interval follows
   the fastest child (c*), so at a fan-out it can't pace the slower
   children. Forwarding every output immediately was tried: the slow
   child was overrun, about 300 wasted transfers per 20 s run in
   fanout-join against about 1. On a single chain it made no difference.

2. The Source keeps its schedule on renewals with an unchanged seq. Idle
   heartbeats (phase 0) re-anchored the grid. After subtracting R, T and
   RTT, their phase is negative and wraps to nearly a full I ahead. With
   I > W, each renewal pushed the next send out again before it fired, and
   the edge starved: 0.29 results/s on the real stack with I ≈ 110 ms and
   W = 50 ms.

3. A re-anchored Source send is held until last_send_t + I − ε. Demands
   with a new seq can arrive faster than I (an interior node's seq rises
   with every frame it receives). Re-anchoring on each one made the Source
   send at the demand rate and ignore I. Holding the send keeps "at most
   once per interval" without skipping a whole interval.

4. "Never send the same output twice" compares producer ids (run id at
   engines, sample id at the Source), not sample timestamps. A partial join
   run can carry an older newest timestamp than the previous run while
   still being new output, so a timestamp check would drop it.

5. Pacing uses medians: best / worst use r at PACE_PCT = 50 (was p80), and
   T uses TRANSMIT_PCT = 50 of time per byte (was p90). Leases stay on p80.
   - Committing to p80 capped throughput at 1/p80. Per-run re-anchoring
     made it worse: early send times are clipped to I but late ones are
     taken, so the average gap exceeds I. Virtual time, detect at mean
     60 ms and cv 0.3: 10.9 -> 15.7 results/s (token: 16.5).
   - On a real QUIC link, T at p90 set the pace instead of R (aioquic
     spreads each frame over about one RTT). Real stack via proxy, 50 KB
     frames at 50 Mbit/s and 46 ms RTT: 9.5 -> 12.4 results/s, with median
     latency up about 40 ms.
   - Cost: an occasional input overwritten when a run or transfer is
     slower than the median.
   - Both are parameters (pace_pct, transmit_pct); 80 and 90 restore the
     original behavior.

6. (Removed.) A lease jitter allowance J = p99(rtt) − min(rtt) on network
   edges was tried. It removed lease flaps only under extreme (±120–200 ms)
   link jitter and never changed throughput, so it was taken out.

7. Source sends the next frame when a slot finds none newer. If the send
   timer fires before a new frame exists, the edge is marked waiting and
   the next frame goes out as soon as it arrives. The slot is not skipped.
   This is CLAUDE.md principle 8 ("sends right after a frame arrives").

8. seq is kept per parent edge and updated on arrival. The original kept
   one n.seq, set at collect. A partial join run whose inputs are older
   would lower it, and the faster parent would then discard the demand as
   stale. Per-edge seq matches CLAUDE.md ("a join keeps one per parent")
   and is monotonic per edge.


===========================================================================
segment protocol (mode "segment")
===========================================================================

Idea: pull on local edges, fixed tokens on remote edges. Local edges are
cheap and on one host, so a child just asks for input when it is idle.
Remote edges cross the network, where timing estimates are fragile, so
each one gets a fixed number of tokens instead. No phase, interval,
lease, RTT/T estimate or send grid is used anywhere.

definitions:
	local edge:   parent and child on the same side of the network
	remote edge:  the edge crosses the client <-> remote link
	remote branch: one remote edge, seen from its sender (the parent)
	fan-out:      a node with several children, or with any remote child.
	              (Any edge crossing the network therefore leaves from a
	              fan-out, implicitly.) A fan-out forwarding a frame ends
	              the remote branch that frame arrived on.

constants / parameters:
	segment_remote_tokens = 6      fixed tokens per remote branch
	token_timeout_ms      = 2000   reclaim / un-park after this long
	ping every 100 ms; link counts as down after 500 ms without a reply

state:
per node, as a parent:
	want[c]:   local child c is idle and asked for input (bool)
	held[c]:   for local child c, at most one output ready for it:
	           [item, upstream stamps, reported]
	per remote child c (a branch):
		n:       segment_remote_tokens
		out:     frame id -> [state: out | parked, time]
	next_id:   frame ids for this node's remote sends
	copies:    frame id -> [remote recipients left, used by any]
	link_up:   the client <-> remote link, as this node sees it
per node, as a child:
	requested[q]: a want is outstanding to local parent q
	in_stamps:    stamps of the inputs of the current run
per Source:
	last_sent[c]: newest frame id sent to local child c

per message (data), extra fields:
	seg: stamps [[head, branch child, frame id], ...] of the remote
	     branch(es) the frame is travelling on (empty on local-only paths)
	mc:  number of children one remote copy was addressed to
per message (control):
	want  {to: parent}                      local child is idle
	seg   {to: head, ev: [[child, id, what], ...]}, what: used | drop | lost
	link  {up: bool}                        client -> local server

addressing: one copy can be addressed to several children on one host
	as "a+b"; the receiving host delivers it to each. On receipt, a node
	keeps only the stamps for its own branch:
		drop stamp s if s.head == sender and s.child != self

local edges (pull):
child n, for each local parent q:
	deliverable(n) = n is a leaf
	              or some remote child of n has a free token
	              or some local child of n has no held output
	request:  when n is not running and deliverable(n):
	              for each local parent q with slot q empty and not requested[q]:
	                  send want to q; requested[q] = true
	          (called at start, after every run, and whenever n's capacity
	           changes: a want arrives, a token returns, the link comes up)
	on data from q: requested[q] = false
	run when: the usual slot rules (all slots full, or grace for joins)
	          AND deliverable(n)          # nothing could take the output: wait
	remote parents: no wants; their frames arrive as their tokens allow

Source s, on want from local child c:
	f = s.newest_frame()
	if f exists and f.id > last_sent[c]: send f to c now; want[c] = false
	else: want[c] = true                  # send the next frame on arrival
Source s, on new frame f:
	for each local child c with want[c]: send f to c; want[c] = false
	send_remote(f)

engine n, on want from local child c:
	if held[c]:
		send held item to c
		if its stamps were not reported yet: report used(stamps)
		    (and mark other held copies of the same item reported)
		delete held[c]
	else: want[c] = true
	capacity changed: maybe run, request

remote edges (fixed tokens):
free(c) = link_up and |branch c.out| < n

send_remote(item):                           # arrival-driven, sent once
	ready = [remote children c with free(c)]
	if none: return false
	id = ++next_id
	for c in ready: branch c.out[id] = [out, now]
	copies[id] = [|ready|, false]
	for each host h among ready:
		send one copy to "c1+c2+..." (ready children on h) with
		    seg = [[self, c, id] for each of them], mc = their count
	return true

engine n, on output y of a run (in_stamps = stamps of the run's inputs):
	if n is not a fan-out (exactly one child, local):
		y.seg = in_stamps                    # stays on the same branch
		if want[child]: send y; want[child] = false
		else: hold(child, y, in_stamps, reported = false)
		return
	sent = send_remote(y)                    # y gets fresh stamps there
	clean = y without seg
	wanting = [local children c with want[c]]
	if wanting: send one copy of clean to "w1+w2+..."; clear their wants; sent = true
	for each other local child c: hold(c, clean, in_stamps, reported = sent)
	if in_stamps:
		if sent: report used(in_stamps)      # a fan-out forwarding it ends the branch
		else if clean is held nowhere: report drop(in_stamps)

hold(c, item, stamps, reported):
	old = held[c]; held[c] = [item, stamps, reported]
	if old had stamps, was not reported, and is held for no other child:
		report drop(old stamps)              # replaced before anyone took it

ends of a remote branch's chain (reported to its head):
	used:  a leaf produced a result from it
	       a filter rejected it
	       a fan-out forwarded it to some child (or a held copy was taken)
	drop:  overwritten in an engine's slot (skip)
	       a held output carrying it was replaced before being taken
	       replaced in a sender slot while passing through (not the
	       head's own copy)
	lost:  the head's own copy was replaced in its sender slot before
	       leaving (reported by the host that replaced it)

head, on seg events [child, id, what]:
	rec = branch child.out[id]; ignore if missing or parked
	used:        delete rec; copy_done(id, used = true)
	drop / lost: (frame unused on this branch)
	             copy_done(id, used = false)
	             if another frame of this branch is still out (not parked):
	                 park rec (state = parked, time = now)
	             else: delete rec
	capacity changed: maybe run, request

copy_done(id, used): when every remote recipient of copy id has reported
	and none used it, it was a wasted transfer (metric only).

every token_timeout_ms / 4 (reclaim tick), if link_up:
	for each branch:
		parked entries older than token_timeout_ms: release at most one
		    per branch per tick (oldest first)
		out entries older than token_timeout_ms: release (reclaimed: the
		    frame or its report was lost)
	capacity changed

link (remote heads only):
	link down:  link_up = false; no remote sends (free() is false); no
	            reclaiming, so the branches' tokens are held
	link up:    link_up = true; clear every remote branch's out (frames
	            in flight were lost); capacity changed
	sources of link state:
		client:        QUIC link to the remote server up / down; no ping
		               reply for 500 ms -> down, next reply -> up (the
		               silence clock restarts when QUIC connects); tells
		               its own nodes and sends link{up} to the local server
		local server:  link messages from the client
		remote server: client connected / disconnected; no ping reply for
		               500 ms -> down, next reply -> up

properties:
	- a local consumer of a Source never waits on a queued input: it gets
	  the newest frame the moment it is idle
	- between local engines at most one output is kept ready per child
	  (no pipeline bubbles); it can age by up to the child's run time
	  minus the parent's when the child is slower
	- a remote branch has at most n frames out; skips park tokens, so an
	  oversized n takes its excess out of circulation for token_timeout_ms
	- each frame crosses the link once for all remote children that have
	  a token; children without one skip it on the sending side, for free
	- no estimates: the only timer is the token timeout

joins: a join pulls from each local parent separately and gets frames from
remote parents as their tokens allow; its output carries the stamps of all
its inputs, so finishing it reports to every head involved.

not covered: segment_branch_tokens = false selects an older version with
one token pool per local / remote group and held outputs at heads; it is
kept only for comparison.
